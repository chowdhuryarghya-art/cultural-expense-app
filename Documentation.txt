CREATE SCHEMA cultural;

CREATE TABLE cultural.financial_year (
    id SERIAL PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    start_date DATE NOT NULL,
    end_date DATE NOT NULL
);

CREATE TABLE cultural.events (
    id SERIAL PRIMARY KEY,
    financial_year_id INT REFERENCES cultural.financial_year(id),

    name VARCHAR(100) NOT NULL,
    description TEXT,
    event_date DATE NOT NULL,
    budget NUMERIC(12,2)
);

CREATE TABLE cultural.income (
    id SERIAL PRIMARY KEY,
    event_id INT REFERENCES cultural.events(id),

    source VARCHAR(100) NOT NULL,
    amount NUMERIC(12,2) NOT NULL,
    income_date DATE NOT NULL,
    received_from VARCHAR(100),
    block VARCHAR(100),
    flat_no VARCHAR(100),
    payment_mode VARCHAR(50),
    payment_status VARCHAR(20),
    notes TEXT
);

For an existing database, apply
backend/migrations/20261003_update_income_details.sql to preserve existing
recipient names while renaming received_by to received_from and adding block
and flat_no. Also apply
backend/migrations/20261003_add_income_soft_delete.sql so existing databases
have the soft-delete flag used by the income API. New income source options are
Puja Donation, Sponsorship, and Subscription. Apply
backend/migrations/20261004_add_income_payment_status.sql to add payment_status;
Puja Donation records use Paid or Pending. Sponsorship and Subscription
records are automatically saved with a Paid status.

Bulk income upload
==================

Open the Bulk income tab, download income-upload-sample.csv, replace the sample
rows, choose the event, and upload the CSV. Upload one event per file, with up to
1,000 records (4 MB maximum). Keep the headers shown in the sample. Required columns are
source, received_from, amount, and income_date; optional columns are block,
flat_no, payment_mode, payment_status, and notes. Puja Donation rows require
payment_status to be Paid or Pending. Sponsorship and Subscription rows are
automatically saved with a Paid status; leave payment_status empty for these
sources. Use one of the three supported sources, positive amounts with up to
two decimal places, and dates in YYYY-MM-DD format.
The import validates every row before saving and inserts all records together;
if validation fails, no records are saved.

User accounts
=============

Existing databases must apply backend/migrations/20261004_add_authentication.sql
before starting the authenticated app. Users may register from the login screen
using a name, email, and password of at least 10 characters. Sessions last up
to 7 days in the current browser session. All registered users currently have
the same application permissions; role-based access is not configured.

Meal ordering
=============

Apply backend/migrations/20261007_add_meal_orders.sql after
backend/migrations/20261004_add_authentication.sql. This creates a separate
festival meal menu and order schema and seeds the Skyline Lakeview Durgotsav
2026 menu for October 17-21. Then apply
backend/migrations/20261008_add_meal_order_head_count.sql to add head counts
to each saved meal. Apply
backend/migrations/20261009_allow_multiple_meal_options.sql to allow several
options for one meal in the same order. If the headcount summary reports that
head counts are not set up, apply
backend/migrations/20261010_ensure_meal_order_head_count.sql and restart the
backend. Apply backend/migrations/20261011_add_meal_resident_directory.sql,
then populate cultural.meal_order_blocks and cultural.meal_order_flats with
the site's block names, flat numbers, and owner names. Apply
backend/migrations/20261012_add_meal_flat_owner_name.sql to add the owner_name
column to existing installations. Set
cultural.meal_order_settings.subscription_event_id to the Durgotsav event ID
in cultural.events. The app uses a non-deleted Subscription income record for
that event and the selected block/flat to determine subscription payment.
Apply backend/migrations/20261013_add_meal_order_phone_number.sql to add the
phone_number column to existing installations. Meal orders require and store
an international phone number including country code. After saving, the app
opens a prefilled WhatsApp chat with the order details; the user must press
Send. This click-to-chat flow has no WhatsApp API message charge.
Apply backend/migrations/20261014_add_meal_order_update_receipt.sql to store
the latest order additions for update receipts. Editing an order recalculates
the updated order total; the update receipt, WhatsApp message, and additional
amount due include only newly added meals or increased head counts. Removed
meals do not offset the additional amount.
Open Meal ordering, select a block and flat, then select any combination of
meal options and enter a separate head count from 1 to 10,000 for each. Meal
selection and saving are disabled until both a block and flat are selected;
the flat owner's name is then displayed. Flats without a paid Subscription
show "Subscription is not paid" and cannot place or save meal orders. Astami's
complimentary lunch is enabled only for flats with a paid subscription. Meals
may be skipped.
The server calculates totals using saved menu prices and head counts. The Meal
orders tab lists every order, provides a details view, and allows editing
partial orders. The Meal headcount summary tab filters by day and shows totals
by meal, food type, and option. A Print receipt button is available after
saving an order and in the order details view. It opens the browser print
dialog with an 80 mm thermal receipt layout; select the connected POS printer
and adjust printer settings as needed.
The Unpaid subscriptions tab lists active flats across all configured blocks
that do not have a Paid Subscription for the configured Durgotsav event,
includes flat owner names, and can export the displayed list to CSV.

    category VARCHAR(100) NOT NULL,

Windows launcher
================

Double-click CulturalExpenseApp.exe in the project folder to start the backend
and frontend. The launcher waits until the backend and frontend respond, then
opens http://127.0.0.1:5173 in the default browser.

Requirements:
- Node.js must be installed and available on PATH.
- Run npm ci once in both the backend and frontend folders.
- Configure backend/.env and make PostgreSQL available before launching. For
  the included Docker database, run docker compose -f docker/docker-compose.yml
  up -d postgres from the project folder.

The launcher window can be closed without stopping the services. To stop them,
press S then Enter in that window, or double-click StopCulturalExpenseApp.cmd
after the launcher window has been closed. Service output is written to logs/.
To rebuild CulturalExpenseApp.exe after changing the launcher, run
launcher\build.ps1 in Windows PowerShell.
